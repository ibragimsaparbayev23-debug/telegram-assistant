# Telegram Assistant — Railway

Личный ИИ-помощник: ответы от вашего аккаунта в выбранных группах и личных чатах.
Вход через веб-страницу сервиса. Код и пароль Telegram не вводятся в GitHub или ChatGPT.
Ключи задаются в Railway Variables, сессия сохраняется на подключённом Volume.

## Загрузка в GitHub

Распакуйте архив и загрузите файлы из папки Telegram_Assistant_Railway в корень
своего закрытого репозитория telegram-assistant: Add file → Upload files → Commit changes.
Файлы Dockerfile, server.py, assistant.py и requirements.txt должны оказаться в корне.
Сам ZIP загружать не нужно. Не добавляйте ключи или папку data в GitHub.

## Подключение к Railway

1. В уже созданном проекте Railway выберите GitHub Repository.
2. Разрешите Railway доступ только к репозиторию telegram-assistant и выберите его.
3. Подключите к сервису Volume с путём монтирования `/data`.
   В интерфейсе может называться Add volume / Create volume; если для вашего аккаунта
   эта функция недоступна, не продолжайте вход в Telegram до подключения постоянного диска.
4. В Variables сервиса добавьте значения из таблицы ниже.
5. Примените изменения и дождитесь успешного развёртывания. Dockerfile и railway.toml
   уже включены, команда запуска — `python server.py`.
6. В Settings → Networking → Public Networking нажмите Generate Domain. Порт сервиса —
   значение PORT, которое задаёт Railway (программа использует его автоматически).
7. Откройте полученный HTTPS-адрес. Введите ваш ADMIN_PASSWORD.
8. На защищённой странице введите номер телефона, затем код Telegram и, при наличии,
   пароль двухэтапной защиты. Данные ввода не записываются в логи программы.
9. Выберите тестовую группу или нужные личные чаты и подтвердите согласие участников
   на обработку текста сообщений ИИ. Нажмите «Включить ответы».
10. С другого аккаунта отправьте в выбранной группе текст с @упоминанием вашего
    личного username. Проверьте, что ответ пришёл от вашего профиля.

| Railway Variable | Что указать |
| --- | --- |
| TELEGRAM_API_ID | API ID приложения на my.telegram.org |
| TELEGRAM_API_HASH | API hash того же приложения |
| OPENAI_API_KEY | Ключ вашего проекта OpenAI с доступными средствами или кредитами |
| ADMIN_PASSWORD | Придуманный вами уникальный пароль управления длиной от 24 символов, например случайные латинские буквы и цифры |
| OPENAI_MODEL | Необязательно: по умолчанию gpt-4.1-mini |

Не используйте в ADMIN_PASSWORD пароль Telegram или GitHub.
Все настоящие значения вводите в Variables Railway, их нет в этом архиве.
Не задавайте DATA_DIR, PORT или RAILWAY_VOLUME_MOUNT_PATH вручную: последний параметр
Railway предоставляет после подключения Volume.

## Как работает

- Ответы только в выбранных чатах.
- В группах — на @упоминания вашего аккаунта и ответы на ваши сообщения.
- В личке — на новые текстовые сообщения в выбранных диалогах.
- Только новые сообщения после старта. Офлайн-история не обрабатывается.
- Текущая версия отправляет в OpenAI только текст обращения, до 6000 символов.
  Она не знает вашу историю ChatGPT или сведения о клиентах; факты можно добавить
  в instructions.txt и заново развернуть программу.
- Пароли и платежи, личные решения и обязательства передаются вам уведомлением в
  «Избранное» согласно инструкции модели. Это не строгая гарантия фильтрации.
- Голос, файлы и изображения не распознаются; подпись к файлу может обрабатываться как текст.
- Лимит: одна попытка на чат за 30 секунд и 100 запросов ИИ за день UTC.
  Пропущенные сообщения и неудачные отправки автоматически не повторяются.
- В Избранном: `.ai off` — пауза; `.ai on` — включение; `.ai status` — состояние.
- На веб-странице кнопка «Пауза и выбор чатов» останавливает текущие ответы и позволяет
  изменить список. При отзыве согласия исключите соответствующий чат.
- Если после перезапуска сохранены авторизация, список чатов и включённый режим,
  помощник запускается автоматически. Если он был на паузе, включите его через страницу.
- Развёртывайте только одну реплику: одновременный доступ к файлу сессии не поддерживается.

## Секреты и данные

Публичный адрес открывает только страницу входа; доступ к управлению защищён отдельным
паролем. Не публикуйте пароль управления и адрес сессии браузера. После изменения
ADMIN_PASSWORD в Railway потребуется повторно войти в управление.
Cookies действуют 8 часов, имеют Secure, HttpOnly и SameSite=Strict. Действия защищены
проверкой Origin и CSRF-токена. Журнал HTTP отключён. Код/пароль Telegram не сохраняются
программой, но файл сессии даёт доступ к аккаунту. Управляйте устройствами в Telegram.

На Volume находятся config.json (включая рабочие ключи), account.session (авторизация
и служебный кэш Telethon), state.sqlite (ID обработанных сообщений и счётчик запросов).
Тексты переписки не сохраняются в базе программы. Защитите доступ к аккаунту Railway,
его участникам и резервным копиям Volume. Удаление Volume уничтожит сессию и настройки.
store=false в запросе OpenAI отключает сохранение объекта Response; это не обещание
отсутствия служебного хранения у провайдера. Политика: https://developers.openai.com/api/docs/guides/your-data.

## Кредиты и ограничения

Railway — хостинг; OpenAI API оплачивается отдельно с учётом доступных кредитов.
Не предполагается, что бесплатного кредита Railway хватит на месяц работы 24/7:
это проверяется по Usage после запуска. При исчерпании кредита сервис может остановиться.
Healthcheck `/health` подтверждает работу веб-сервера, а не подключение Telegram или
наличие средств OpenAI. Состояние помощника проверяйте на защищённой странице.

## Проверка кода

```bash
pip install -r requirements.txt
python -m unittest -v test_assistant.py test_server.py
```

Проверены маршрутизация чатов, пауза, дедупликация, отмена ответов при изменении/удалении,
счётчик запросов, формат запроса OpenAI, подпись и срок cookies, CSRF, запрет внешних
Origin, защита постоянного хранилища и контроль выбора чатов/согласия.
Реальные Telegram/OpenAI и развёртывание Railway требуют ваших доступов и пока не проверены.
